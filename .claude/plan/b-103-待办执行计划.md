- 准备：docker-compose.yml **两处** `GOTRUE_JWT_EXP`（app env ~:30 + gotrue 服务 :123）同改 `"120"` → `up -d`；内网 http 须 `COOKIE_SECURE=false`（B21 坑）。exp=120 < 刷新窗 600s ⇒ 每请求必触发刷新，放大观察面。
- **场景 1 续期不掉线**：登录记 cookie → 每 ~40s 导航持续 ≥5min → 预期不弹 /login、新 access **exp 持续后移 + 全程不掉线**（评审修订 4：`REFRESH_TOKEN_REUSE_INTERVAL` 内可能返回同一 refresh token，「每次必轮换」会误报，token 偶发不变不计 bug）；反向佐证=场景 2 中 2min 必掉证明 exp 真生效。多标签并发竞态是已知取舍不计 bug。
- **场景 2 停 GoTrue fail-closed**：`docker compose stop gotrue` → 2min 内导航**预期仍正常**（旧 payload 有效，仅日志刷新失败）→ 过期后导航预期 302 /login + Set-Cookie 清两枚 → `start gotrue` 恢复。
- **场景 3 ban 后续期失败**：A 登 operator、B 登 SUPER_ADMIN 在 `/system` 禁用 A → A 在 access 有效期内仍可访问（**预期**，JWT 无状态）→ 过期后 A 导航被 GoTrue 拒 → fail-closed 302 + 清 cookie。关单口径：「ban 生效延迟 ≤ GOTRUE_JWT_EXP」为设计行为，呼应待办 §四「生产 exp 改 ≤3600」。
- 收尾：compose 改回 `"604800"` + `up -d`。

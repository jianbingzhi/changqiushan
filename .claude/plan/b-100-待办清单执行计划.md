### A3 B23 每日滚动生成(cron)

**核心用例**(`booking/service/slot-roll.ts`,双触发壳共用):
```
rollGenerateSlots(horizonDays = SysConfig["slot.horizon_days"] ?? 14):
  today = chinaToday()                       // 复用 Asia/Shanghai 工具(seed 时区 bug 前车之鉴)
  templates = repo.listEnabledTemplates()
  overrides = repo.listHolidayCalendar(today .. today+N)
  for offset in 0..N:
    date = today + offset
    ov = overrides[date]
    if ov?.closed: continue
    dayType = ov?.dayType ?? inferDayType(date)
    for t in templates.filter(t => t.dayType == dayType):
      createManySlots(date, t) ON CONFLICT (date,start_time) DO NOTHING   // 幂等
```
- **幂等是命门**:`@@unique([date,startTime])` 已存在;`ON CONFLICT DO NOTHING` 保证重复跑 + 与手动建时段共存安全。**绝不 UPDATE 已存在时段的 capacity**(会冲掉运营手动调整)。
- **守边界**:dayType→模板来自 booking 自身的 `SysSlotTemplate`(同模块,无跨模块问题);`slot.horizon_days` 等 SysConfig 经 `import { getConfig } from "@/modules/system"`(经 index,合法,**与 A1 口径一致,审计 F7**)。**不必为此走 route 层兜底**(原"依赖倒置"写法过度保守,除非出现循环依赖再退回 route 组合)。
- **双触发壳(本项最大差异)**:
  - 自托管:`instrumentation-node.ts` 用 **pg-boss `schedule('roll-slots','0 18 * * *')`**(已有 boss 单例,`if(VERCEL)return` 天然隔离)。
  - Vercel Hobby:`vercel.json` 加 `{path:"/api/cron/roll-slots", schedule:"0 18 * * *"}`(UTC 18:00 = 北京 02:00),CRON_SECRET 鉴权(复用 refresh-mv 范式)。**⚠️ Hobby cron 上限 2 个**:现有 refresh-mv(1)+ roll-slots(2)=触顶,日后再加须合并到一个 route。
  - 两壳都只是薄壳,都调 `rollGenerateSlots()`,一份逻辑两入口。
- 验证:删未来某日时段 → 打 cron route(带 secret)→ 该日按 dayType 生成;重复打两次确认幂等;某周一标节假日 → 重生成验证配额切换。

## BE-C 会话滑动续期(B16)★★(生产前阻断)

> 现状:登录只写 `sb-access-token`(maxAge=`Number(GOTRUE_JWT_EXP) || 3600`,**审计 F6**:演示设了 7 天故为 7 天、env 缺省则退 1h),**从不存 refresh_token**(核心前提,已核验)。生产把 exp 调短(如 3600)后 = 用户每小时被踢,无续期通道。

- **双路统一走 GoTrue refresh(不本地重签)**:自托管 HS256 虽理论可本地重签,但会**绕过 GoTrue 的 ban/吊销语义**(`banAuthUser` 失效),故两环境统一 `fetch(GOTRUE_URL + /token?grant_type=refresh_token)`。Edge runtime 可 `fetch` + 写 response cookie,`jose` edge 安全。
- **方案 A(推荐)middleware 临近过期主动刷新**:
  1. 登录时**额外存 `sb-refresh-token`**(httpOnly+secure+sameSite=lax,maxAge 取 refresh 寿命)。
  2. middleware 验签后若 `exp - now < 10min` → fetch GoTrue refresh → 写回新 access+refresh 两个 cookie。
  3. 新增 `shared/auth/refresh.ts`(edge 安全,仅 fetch+jose)收口,登录与 middleware 复用。
  4. 刷新失败 **fail-closed 重定向 /login**,别静默放行。
- **风险**:refresh_token 轮换——Supabase/GoTrue refresh 会轮换 refresh_token,**必须把新返回的写回 cookie**;并发刷新竞态用"窗口够宽(剩 <10min 才刷)+ GoTrue `REFRESH_TOKEN_REUSE_INTERVAL=10`"缓解;`GOTRUE_URL` 在 edge 须公网可达(Vercel 上不能 localhost)。
- **演示可暂避**:演示环境 JWT 设长时效(24h/7d)就不被踢,B16 可延后到**自托管生产前**真正落地。
- 验证:`GOTRUE_JWT_EXP=120` 起本地,登录后持续操作 >2min 不掉线且 access token `iat` 推进;停 GoTrue 后操作被重定向;`banAuthUser` 后下次刷新失败被踢。

### BE-C 关键文件
`login/page.tsx`(存 refresh_token)、`middleware.ts`(临近过期分支)、新增 `shared/auth/refresh.ts`、`session.ts`、`jwt-verify.ts`(分支口径复用 GOTRUE_JWKS_URL 是否存在)。

## BE-E 部署善后(§四)—— 纯运维,无代码

> 安全原则:token 在对话明文出现过 = **视为已泄露,务必轮换而非仅停用**。
> **〔审计 F1 · 时序拆两段,消除"立即/演示后"矛盾〕** 已泄露的是**活令牌 + 弱口令**,展示期内任何人都能凭其操作你的 Supabase/Vercel/GitHub。但**改 DB 密码会打断正在跑的演示站**。故按"影响面 vs 是否打断演示"拆开:
> - **第①段(立即,不影响演示)**:撤销三个外部 token——它们与演示站运行无关,留着纯属暴露面,**现在就撤**。
> - **第②段(演示结束后)**:改 DB 密码 / 删测试账号 / 暂停项目——会动到运行态,排到演示收尾。

# 第二部分 · 前端「一次 theme pass」

> 决策遵守:纯视觉项**不逐页 hack**,统一收口 theme(深浅双主题),**最后一次性调**,不必 100% 还原设计图。**批次顺序不可乱**——跳过 FE-1 直接做 B18/B14 会在没 token 时再写一批 hex,制造新债。

## FE-1 Token 地基 ★★★(纯 globals.css,不碰任何页面,风险最低收益最大)

- **补全 shadcn 抽象语义 token**(组件已在引用但 `@theme` 缺失):`foreground/muted/muted-foreground/accent/accent-foreground/input/ring/popover/popover-foreground/card-foreground/destructive`。**〔审计 F5〕`background`(globals.css:14)、`card` 已存在**——这两个是**改成 `var()` 双层**(纳入双主题),**不要当缺失重新声明**;`text-muted` 也已存在(与新加的 `muted-foreground` 不同名,保留)。保留现有 `primary/sidebar/text-*` 别名做向后兼容。
- **双主题正确姿势(Tailwind v4)**:`@theme` 的值用 `var(--xxx)`(**不可写死 hex,否则编译期固化、主题切不动**),实值放 `:root`(浅)/`.dark`(深):
  ```css
  @theme { --color-background: var(--bg); --color-foreground: var(--fg);
           --color-muted: var(--muted); --color-ring: var(--ring); /* ... */ }
  :root { --bg:#F9FAFB; --fg:#1F2937; --muted:#F3F4F6; --ring:#2D5A27; /* ... */ }
  .dark { --bg:#0F1713; --fg:#E8EFE3; --muted:#1A241E; /* ... */ }
  ```
- **切主题机制**:`.dark` class on `<html>` + `@custom-variant dark (&:where(.dark, .dark *))` + **`<head>` 内联同步脚本防 FOUC**(水合前读偏好/localStorage 打 class)。此脚本与 FE-3 的 B14 折叠态预置**合并写,一次注入双用**。
- **分期取舍**:若双主题想分步,FE-1 可先只补 token 浅色实值(修好 B19 假 token),`:root/.dark` 分层留接口——但终点必须是双主题(用户目标)。
- **立即收益**:Input 边框/ring、Table 表头灰字/hover/斑马纹"复活",B19 自动好一半。
- 验证:`tsc --noEmit` + docker 构建目视 Input/Table 样式出现。

## FE-2 基础组件(B19 表格 + B20 按钮 + Input 图标)★★

- **B19 表格**:token 补全后 `table.tsx` 的 hover/表头自动复活;加**密度 prop**(cva:comfortable 默认 / compact)、**斑马纹**(`nth-child(even):bg-muted/40`,用 token 非 `bg-gray-50`)、**对齐约定**(数字/金额/时间 `text-right tabular-nums`,状态/操作 `text-center`)。**不做** DataTable 高阶封装(16 页迁移超出 theme pass 范畴)。

## FE-3 布局类(B24 露白 + B14 折叠 + B9 收尾)★★

- **B24 侧边栏露白**(根因已定位):`(admin)/layout.tsx` 根 `flex h-full min-h-screen` + `aside h-full`,`h-full` 在内容超屏时不跟长 → 侧栏停视口底露 `#F9FAFB`。**修法**:根容器 `flex min-h-screen`(去误导的 `h-full`),`aside` 去 `h-full` 靠 flex `align-items:stretch` 自动拉满;内部已有 `overflow-y-auto`。顺手 `style={{backgroundColor:"#F9FAFB"}}`→`bg-background`(B9+双主题双收)。**最终可选升级**:双独立滚动区(侧栏 `sticky h-screen` + 主区独立滚),本次 A 法止血即可。
- **B14 菜单折叠**:每组标题→`<button aria-expanded>` + 可折叠 `<ul>`(原生 `<details>` 或自写,**不新增 radix-accordion 依赖**)。记忆态:**推荐用 cookie(SSR 可读,天然无闪烁)** 而非 localStorage——若清单点名的 localStorage 可放宽,cookie 是更优工程解;若坚持 localStorage 则靠 FE-1 的 `<head>` 内联脚本在水合前预置(脚本初始态必须 === useState 初始值,防 mismatch)。**当前激活项所在分组强制展开**(pathname 命中覆盖记忆态)。
- **B9 内联 style 收尾(剩 26 处,审计纠正计数,原写 23——以 `docs/待办清单.md` 的 61→26 为准)**:判定准则——值是**数据/计算产物**(进度条 `width:${pct}%`、状态映射色、图表高度)→**保留**;值是**有限枚举/静态/布尔三元**(layout 的 `#F9FAFB`/`padding:24`、`color:warn?"#DC2626":"#6B7280"`)→ 转 `cn()` + token。转换时**顺带 hex→token**,让 B9 同时服务双主题。大屏 `_big-screen.tsx` 的 `#0B1A2B/#7F1D1D` 升级为深色场景 token。

> **〔评审修订摘要 2026-06-08〕** 三路代码核对后:

> - **F3🟡 bubble-menu v3 引入方式**:TipTap v3 的 BubbleMenu 包名/引入路径与 v2 不同,引入前先确认 v3 正确用法。

## 〇、现状与渲染器结论(代码核对)

- 编辑入口 `src/app/(admin)/content/_content-form.tsx`:**表单卡片**(标题 + 摘要 textarea + `RichTextEditor` 正文 + 网格元数据)。
- 富文本 `src/lib/ui/editor/RichTextEditor.tsx`:TipTap v3,12 钮,**插图仅粘 URL**、无视频、无上传。
- 封面 `coverImage`:三模型 `kind:"url"` 纯文本框;schema `z.string().max(255).optional()` 存 URL 即可,**不改 schema**。
- 排序 `sortOrder`:**仅 intro / knowledge** 有(详情页数字框);列表 `orderBy:[{sortOrder:asc},{createdAt:desc}]`。news 按 `publishedAt`、activity 按 `startDate`,**不手排**。
- 上传基建**已就绪**:`assets/actions.ts` 的 `presignUploadAction` + 浏览器 `PUT` + `commitAssetAction`;`_asset-library.tsx onPick` 是完整范例。
- **消毒:无**,正文/摘要原样存库。
- **〔F1〕渲染器**:`MpHtml.tsx = <RichText nodes={html}/>`(weapp `<rich-text>`)。**渲染器 ∩ 编辑器**的可用标签基线:
  `p · h2 · h3 · strong · em · del(=删除线,须让 TipTap 输出 <del> 而非 <s>) · ul · ol · li · blockquote · a(渲染但不可点跳) · img`。
  **不支持**:`video · iframe · script · style · 任意 class/自定义属性`。

## 四、P2-③ 「文档模式」编辑器 + 白名单消毒护栏

### 4.1 先决护栏:正文白名单消毒(P2 第一步,先于放开编辑器)
- **服务端消毒**:`contentService.save*` 内保存正文/摘要前过 `sanitize-html`(Node 端,F4),白名单 = P0 定的**单一来源常量**(对齐 `<rich-text>`:`p/h2/h3/strong/em/del/ul/ol/li/blockquote/a/img`;`a` 仅留 `href`、`img` 仅留 `src/alt`;**禁** `script/iframe/style/class/任意属性/video`)。
- **不可绕过**:消毒在 service 层,Server Action 与未来 C 端写入共用;客户端编辑器不经 `sanitize-html`,故**每个 `save*` 入口强制执行**。
- **小程序兼容自检**:保存后给"小程序体检"——抽 HTML 标签集比对白名单 + 校验 `img src` 公网可达(非 localhost/相对/内网)。对应 R-mp 检查法。

> **〔实施进度 2026-06-08〕** P1-①(图片)已落 + docker 实测通过(封面/编辑器直传 MinIO 公网读 OK);**修复**:① Dockerfile 在 install 前未拷 prisma schema → postinstall 失败(已加 `COPY prisma.config.ts`+`COPY prisma`);② docker-compose app 服务**缺全部 S3_* env**(预签名直传永远失败,媒体库同病)→ 已补 `S3_ENDPOINT/S3_PUBLIC_ENDPOINT(10.7.0.1:9000)/S3_ACCESS_KEY/SECRET/BUCKET/FORCE_PATH_STYLE`。
> P2-③ 文档画布范式**已落首版**(本节 4.2):`_content-form` 改文档画布 + 属性侧栏;`RichTextEditor` 加 `variant="document"`(无框/吸顶工具栏/正文加高);`ImageUploadField` 加 `variant="banner"`;编辑器图片按钮改**纯上传**(去 URL 次选)。
> **〔2026-06-08 续〕用户「3 项全做完再 push」**——已落:① **白名单消毒护栏**(`domain/sanitize.ts` + `sanitizeRichText`,service `createContent/updateContent` 每个写入口强制过 `sanitize-html`,白名单=渲染器 `<rich-text>` 子集,单一来源常量);② **气泡工具栏**(`@tiptap/react/menus` 的 BubbleMenu,选中浮现 加粗/斜体/删除线/H2/列表/引用;F3 确认 v3 用 `@tiptap/react/menus` 子路径,无需额外包);③ **列表拖拽排序**(`@dnd-kit`,intro/knowledge 列表 `SortableContentRows` + `reorderContentAction`/`reorderContent` service + repo `reorderIntros/reorderKnowledge` 事务整表重排;筛选态禁拖拽;表单删 `sortOrder` 字段)。新依赖:`sanitize-html`/`@types/sanitize-html`/`@dnd-kit/{core,sortable,utilities}`。tsc/eslint/lint-cn/54 单测全绿。

### 4.2 范式重构:表单卡片 → 文档画布 + 属性栏
- `_content-form.tsx` 改左右/抽屉布局:
  - **主区(文档画布)**:封面 banner(点击上传)→ 内联大号标题 → 全宽正文画布(纸张感)+ **气泡工具栏**(选中浮现)+ 可选 `+`/斜杠插块 + 拖图直传。
  - **属性栏(右侧)**:**结构化字段**——状态、**活动** 开始/结束日期·人数上限·报名费、**知识库** 分类、**资讯** 摘要。(intro/knowledge 排序已移列表,不在此。)
- **保留属性栏的理由**:活动日期/名额/报名费、知识分类参与 活动日历/报名名额/报名费→支付/分类筛选,是**结构化数据,不能融进正文 HTML**。故纯文档仅 news/intro;activity/knowledge = 文档 + 属性栏。
- **能力卡白名单**:编辑器**只开 §〇 基线内的块**,不放开任意富文本(Word 那种字体/色/表格/分栏 `<rich-text>` 渲染不了)。
- **试点**:先在 **news 单类型**落范式,稳了再铺其余三类(降重构回归面)。

## R2 · 🚩 SSE 路由无鉴权（评审新发现，确认真漏洞 — 低成本必修）
- 实测：`app/src/app/api/sse/[topic]/route.ts` **无任何鉴权**，仅靠 `ALLOWED_TOPICS` 白名单防注入。任何**未登录**请求即可订阅 `slot_changed / checkin_event / iot_event / parking_state` 四路实时事件流 → 核销/IoT/车位/时段数据外泄。
- 根因：`middleware.ts:43` 的 matcher = `["/((?!_next/static|_next/image|favicon.ico|api/).*)"]`，**负向先行排除 `api/`** → 所有 `/api/*` 不经 middleware，鉴权只能各 route handler 自带；而 SSE route 没带。
- 修法：SSE route 内 `await getSession()`，未登录 401；如个别 topic 需对 C 端访客开放，则按 topic 分级（B 端 topic 必须管理员态，访客 topic 另开 `/api/c/sse/*` 走 `requireVisitor`）。
- 旁证（抽查确认其余 API 已有鉴权，无需动）：`api/export/[module]`=`getSession`+`EXPORT_ROLES{SUPER_ADMIN,ADMIN}` 角色门 ✅；`api/gate/checkin`=`x-gate-key` ✅；`api/c/*`=`requireVisitor`/`requireBoundVisitor` ✅。**唯 SSE 裸奔。**
- 验证：未登录请求 `/api/sse/checkin_event` 返回 401；登录管理员 200。

## R3 · 路由级 RBAC（纵深防御）
- 现状：`middleware.ts` 仅校 cookie 存在 + `jwtVerify(...,{issuer})`，**不读 role**；`middleware.ts:38` 留 `TODO 阶段1: 细粒度 RBAC`。✅核验属实。action 层已是强制点（6 处 `actions.ts` + B08 内联均 `requireRole`）。
- 方案：middleware 自解 JWT 取 `app_metadata.role`，按路由前缀粗粒度拦（`/system/*`→SUPER_ONLY、`/analytics|/content|/riskcontrol`→ADMIN_UP）。
- **⚠️ 实现要点（评审纠正）**：middleware 跑 edge，**拿不到 `next/headers` 的 `cookies()`**（`guard.ts`→`session.ts` 正是用它，故 middleware 不能复用 `getSession`，须从 `request.cookies` 自行取 token 用 `jose` 验）。**注意不是 Prisma 依赖问题**——`guard.ts` 不带 Prisma。
- **角色常量抽离**：`ANY_STAFF/ADMIN_UP/SUPER_ONLY` 当前在 `guard.ts:8-12`（已是零依赖 `as const`）。抽到 `app/src/shared/auth/roles.ts`，middleware 与 `guard.ts` 共用，避免双源漂移。
- 注意：仅纵深防御，**不替代** action 层强制点（后者才是真正堵点）。
- 验证：未授权角色访问越权页面被 302/403；授权放行。（API 侧的门见 R2，不靠本项。）

## R7 · 写操作审计补全 +（防御性）层级校验（P2，越权严重度已降级）
- **审计补全（真缺口）**：`createAdmin(input)@13` / `resetPassword(userId,newPassword)@45` **签名不带 actorId、未写审计**；`disableAdmin(actorId,targetId)@53` 已在 `admin.ts:63` 写 `writeAudit`（范式）。补法：给前两者加 `actorId` 形参 → `system/actions.ts` 透传 `auth.session.userId` → service 内 `systemRepository.writeAudit({actorId,action,resource,detail?})`。
- **⚠️ 越权严重度更正（评审）**：原计划「普通 ADMIN 能重置 SUPER_ADMIN 密码=垂直越权」**不成立**——`createAdminAction/resetPasswordAction/disableAdminAction` 三者 action 层**全部 `requireRole(SUPER_ONLY)`**（`actions.ts:17/27/37`），普通 ADMIN 根本到不了 service。**无当前可利用的垂直越权。**
- **残留（防御性，非紧急）**：service 层缺纵深层级校验 + SUPER_ADMIN 之间无层级（同级互重置/互停用）。可选补：service 内取 actor/target 角色，禁止"权重 ≤ 自己"操作他人/自我降权。**定位为纵深防御**，不是堵当前漏洞，优先级 P2。

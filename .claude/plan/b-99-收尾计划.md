## 优先级与方案

### R1 · 红线 domain 单测（唯一"高价值且该现在做"）
- 现状：全仓**零测试文件**，无测试 runner。纯函数 `app/src/modules/booking/domain/rules.ts`（`assertDualElements:15` / `isCircuitBroken:44` / `canResume:48` 等）易测、回归保险最廉价。
- 方案：装 **vitest**（轻、与 Vite/TS 友好，不与 Next webpack 冲突）。
  - `pnpm add -D vitest`；`package.json` 加 `"test": "vitest run"`、`"test:watch": "vitest"`。
  - 新建 `app/src/modules/booking/domain/rules.test.ts`：
    - `assertDualElements`：身份证校验位合法/非法、车牌(普通+新能源)合法/非法、`plate XOR noVehicleDeclared` 四象限（缺、双、仅车牌、仅声明）。
    - `isCircuitBroken`：89%/90%/91% 边界、capacity=0 防除零。
    - `canResume`：低于恢复阈值才 true、迟滞区间不抖动（`>=0.9` 断 / `<0.8` 恢复的 80–90% 迟滞带）。
    - `canBook`：配额边界 `b+1<=q` 的 off-by-one（满额、差一、超额）、非 ACTIVE 时段拒绝。
    - `canCancel`：`rules.ts:54` 硬编码 `+08:00` 拼串构造 Date —— 正该用单测钉死，覆盖跨时区/临界 2h。
  - 同理可补 `riskcontrol`/`checkin` domain 纯函数（爽约计数阈值、`verifyRotatingCode` 时间窗、`isCurrentSlotValid`）。
- 验证：`pnpm test` 全绿；CI 串入 `pnpm lint && pnpm test`。
- 红线对照：双要素(#2)、90% 熔断(#4) 的纯函数级回归。

### R2 · 路由级 RBAC（纵深防御）
- 现状：`app/src/middleware.ts` 仅校 cookie 存在性 + issuer（`middleware.ts:38` 留有 `TODO 阶段1: 细粒度 RBAC`）；**action 层已是强制点**（6+ 处 actions.ts + B08 内联均 `requireRole`）。
- 方案：middleware 解出 `app_metadata.role` 后按路由前缀粗粒度拦截（如 `/system/*`→SUPER_ONLY、`/analytics|/content|/riskcontrol`→ADMIN_UP）。
- **⚠️ 洞 1 — API 路由不经 middleware**：`middleware.ts:43` 的 `matcher` 是 `(?!_next/...|api/).*`，**所有 `/api/*`（含 `/api/sse/*`）完全绕过本层门**。本项只覆盖页面路由；必须同时**逐一确认每个 route handler 自带鉴权**（SSE topic 路由、任何 route.ts），否则 RBAC 门对 API 无效。
- **⚠️ 陷阱 2 — edge runtime 依赖**：middleware 跑在 edge，**不可直接 import `guard.ts`**（它带 Prisma/node 依赖，会编译失败或污染 edge bundle）。角色枚举须抽成**零依赖纯常量模块**（如 `shared/auth/roles.ts`），middleware 与 `guard.ts` 都 import 它，避免双源漂移。middleware 仅用 `jose`（已在用）。
- 注意：仅作纵深防御，**不替代** action 层强制点。
- 验证：未授权角色访问越权页面路由被 302/403；授权放行；**抽样 API 路由确认无鉴权缺口**。

### R3 · a11y 走查
- `app/src/app/(admin)/system/_account-manager.tsx` 的 `window.prompt` → 内联受控表单（小程序无关，纯 Web a11y）。
- 表单控件补 `<label htmlFor>` 关联；`BarList` 等图表加 `aria-label`/等价数据表。
- 验证：键盘可达、读屏有意义；无 `window.prompt` 残留。

### R4 · X.2 设计系统英文黑名单断言
- 现状：`scripts/lint-cn.mjs` 已扫中文红线（门票/票价/ISO 等）。
- 方案：词表是打地鼠（`Profile/Settings/Logout/Sign up…` 永远列不全）。主力用**启发式正则**——扫 JSX 可见文本里"纯 ASCII 字母 token"，辅以白名单豁免（品牌名、单位 km / PM2.5 等）；黑名单词表保留作快速命中。纳入 `pnpm lint:cn`。
- 验证：植入违规样例能被拦；白名单单位/品牌不误报。

### R5 · B12 高德路况地图（依赖外部 key，按需）
- 现状：`app/src/app/(admin)/traffic/road/page.tsx` 占位；高德 JS API 非 npm、需 key；停车 B13 已附等价数据表(a11y)。
- 方案：取得高德 key 后注入 JS API（`dynamic ssr:false` 客户端岛，走 `NEXT_PUBLIC_*` 注入、不进仓库）；在 key 到位前保持占位 + 等价数据表。**阻塞于外部 key，非代码问题。**
- 安全：高德 web key 务必配**域名白名单**，否则泄漏即被盗刷。

### R6 · 写操作审计 + 越权校验（升级为安全项，非纯 P2）
- 现状：`sys_audit_log` 模型 + `systemRepository.writeAudit({actorId, action, resource, detail})` 范式已存在，`disableAdmin`（`admin.ts:63`）已写；**`createAdmin`/`resetPassword` 未写**。
- **⚠️ 不是加一行**：`resetPassword(userId, newPassword)` / `createAdmin(input)` **签名里没有 actorId**（不同于 `disableAdmin(actorId, …)`）。补审计须先把操作人 UUID 从 action 层透传进来——改签名 + 改调用方（`system/actions.ts` + `_account-manager`）。
- **⚠️ 顺带暴露的越权风险**：`resetPassword` 只校 `requireRole` + 密码长度，**不校验 actor 与 target 的层级关系**——普通 ADMIN 能否重置 SUPER_ADMIN 密码？典型垂直越权。本项升级为：**补 actorId + 写审计 + 校验目标层级（禁止低权重置高权）**。安全价值高于"P2 审计补全"。

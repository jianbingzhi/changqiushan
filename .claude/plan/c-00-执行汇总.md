## 🤖 给执行 AI 的规则（务必遵守）

1. **逐个执行，不并发**：每次只挑一个「状态 = ⬜ 待执行」且其「依赖」全部 ✅ 的子计划，从最上面一行开始。
2. **执行方式**：对该行的计划文件运行 `/multi-execute .claude/plan/<文件名>`（或按计划内 Key Files/步骤逐步实现）。代码只由主 Claude 写，子代理只读。
3. **完成判定（缺一不可）**：
   - 后端类：`cd app && pnpm lint`（eslint-boundaries 零报错）+ `pnpm exec tsc --noEmit` 通过；涉及实时/核销跑 `tsx scripts/verify-realtime.ts`。
   - 前端类：`cd ../Changqiushan-mobile/miniprogram && pnpm taro build --type weapp` 能产出，关键交互真机/开发者工具自测。（小程序工程在 `miniprogram/` 自包含子目录，非 worktree 根。）
   - 打包纪律见 CLAUDE.md：先停 dev + `docker compose down` 再限速，**严禁** `build:fast`/裸 `next build`。
4. **回写本表**：完成后把该行 `状态` 改 ✅、填 `Commit`（短 hash）、`完成时间`、必要 `备注`（坑/偏差/未决项）。**只在用户明确要求时才 commit/push**；未授权则 `Commit` 填「未提交」。
5. **遇阻塞**：若依赖缺失、决策不明或测试卡死，**停下来在该行备注写明阻塞点**并告知用户，不要硬猜带病推进。
6. **红线自检**（每个后端子计划完成前过一遍）：免费预约入园零支付 · 双要素单一校验路径 · 预约前黑名单预检 · 90%熔断 · 动态核销码不下发 secret · 密钥不下发前端 · 100%中文/中文日期/禁门票票价购票退款。

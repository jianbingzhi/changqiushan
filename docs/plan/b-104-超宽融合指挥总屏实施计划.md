# b-104 超宽融合指挥总屏实施计划

> 范围：在已交付 `/screen` C1-C7 大屏基础上，新增 3840×1080 融合指挥总屏。目标是把综合态势、运营趋势、预约热力、数字孪生地图、设备停车与执行边界融合为单块挂墙总屏。

## 一、评审结论

- **计划路径不一致**：仓库原有计划在 `.claude/plan/screen-数字大屏执行计划.md`，不是用户指定的 `docs/plan/b-104-超宽融合指挥总屏实施计划.md`。本次已补齐 `docs/plan/` 版本，后续以本文为 b-104 入口。
- **现有代码只支持 1920×1080**：`ScreenShell` / `useScreenScale` 原先硬编码 1920×1080，无法承载“超宽融合”画布。本次已改为可传画布尺寸，C1-C7 默认 1920×1080 不变，总屏使用 3840×1080。
- **数据安全口径可复用**：现有 `/screen` 无登录架构、`SCREEN_TOKEN` 软门、PII 白名单原则可继续使用。总屏只读聚合仓储，不新增返回原始 Booking、黑名单、申诉数据的接口。
- **熔断职责边界正确**：总屏只展示承载率、暂停时段和红色预警，不触发任何写操作；熔断仍由核销/预约写路径负责。
- **占位边界必须显式展示**：天气/AQI、地域画像、浏览量、三维漫游仍缺外部前置或数据底座，总屏内需保留“待接入”标签，避免演示误读。

## 二、实施方案

### 1. 画布与路由

- 新增路由：`/screen/command`
- 画布尺寸：`3840×1080`
- 缩放策略：复用 `ScreenShell`，通过 `size={ULTRAWIDE_SCREEN_SIZE}` 传入超宽画布。
- 导航入口：`/screen` 增加 `B104 超宽融合指挥总屏`。

### 2. 数据来源

| 区域 | 数据源 | 说明 |
|---|---|---|
| 顶部 KPI | `bookingService.listSlotsForDate`、`configService.getInstantCapacity`、`iotRepository.listDevices`、`trafficRepository.listParkingLots` | 今日预约、核销、剩余名额、承载率、设备在线率、停车负荷 |
| 趋势 | `analyticsRepository.getDailyTraffic` | 近 14 天预约、入园、爽约 |
| 热力 | `analyticsRepository.getWeeklyHourlyHeat` | 7×24 预约热力 |
| 地图 | `contentRepository.listPois` + `AmapContainer` | 高德不可用时降级 POI 列表 |
| 画像/渠道 | `getProfileOverview`、`getVisitorSource` | 年龄段与预约渠道聚合 |
| 活动 | `contentRepository.listActivitiesWithCounts` | 报名中/进行中活动 |

## 四、验收清单

- 页面 `/screen/command` 无登录可访问；配置 `SCREEN_TOKEN` 时需凭据。
- 在 3840×1080、1920×1080、普通笔记本浏览器下都应按比例 letterbox 缩放，无滚动条。
- 承载率达到 90% 时出现红色预警横幅，且页面不发起任何写请求。
- 高德 Key 缺失或加载失败时，地图区展示 POI 降级列表，不空白。
- 画面不得出现票务语义：门票、票价、退款、余额。
- 占位项必须有“待接入”标记。

## 五、剩余风险

- 未接外部天气/AQI、浏览埋点、地域码表和三维漫游，仍为显式占位。
- 当前总屏为 RSC 首屏快照；若需要长时间挂墙自动刷新，可后续把 `/api/screen/[metric]` 的轮询能力扩展到总屏各卡片。
- 真机 3840×1080 视觉还需 Playwright/CDP 截图验收，重点看字体密度、地图降级态和右侧仪表区是否压缩。

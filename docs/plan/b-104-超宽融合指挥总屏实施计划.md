## 0. 背景与现状

- 本屏是**单张融合大屏**（非多页 tab 导航）；定稿 mockup 已落地 7 项改动（删导航 tab、删 3D/图层切换、告警改真实类型、行为偏好改两列、画像改雷达图、天气留/AQI 去、AI 调度面板改「平时空态 + 特殊态可执行编号策略」纯展示）。
- 演示服务器 `156.229.22.155`，推 `deploy-demo` 即自动部署（详见 [[project_demo_server_deploy]] / `app/deploy/README.md`）。
- 现有 6 个分屏（overview/trend/heatmap/operation/situation/twin）全部 **RSC 直读 repo** + 少量 client live 岛（occupancy/SSE）。新屏沿用此模式。
- **后端三端点已实现并上线验证通过**（commit `c846702`，CI run 27949785170 success）：
  - `GET /api/screen/weather` → `{source:"amap", live:{weather,temperature,...}}`，蒲江县 510131，高德 weatherInfo，**不含 AQI**。实测：阴 28℃。
  - `GET /api/screen/profileRadar` → 5 轴雷达（男性/青年18-30/本市成都/自驾/午前），来自 `getProfileOverview`+`getTravelPreference`+`getVisitorRegionByCity`。实测：46/20/40/60/40。
  - `GET /api/screen/dispatch` → 规则模板调度策略，按在园承载率/停车满载/名额售罄/设备告警触发；平时 `calm` 空态、特殊 `alert` 给编号策略；**纯展示无 actuator**。实测命中特殊态。

## 3. 决策（已与用户确认）

1. **路由**：新建 `/screen/command`；现有 `/screen` index 页**顶部加一行入口卡**链向它（两套并存）。
2. **POI 高负荷点位**：真实 POI 名称 + 以 7×24热力/分时负荷做**近似负荷**，诚实标「估算」，不新建 POI 级阈值/计数模型。
3. **中央地图**：沿用 `AmapContainer`（高德非交互暗色底图 + POI 标记）。
   - 风险：JS API key 按域名白名单，demo 纯 IP 访问交互地图可能受限；服务端 key（路况/静态图）不受影响。

## 4. 实施阶段

### P1 数据补缺（后端，小）
- 新增「今日预约按渠道计数/占比」聚合（`bookingRepository` + 经 `channelService` 或新增 `/api/screen/channels`）。
- POI 高负荷近似：在 RSC 内用 `getWeeklyHourlyHeat`/`getHourlyPeak` 当前时段负荷给 `listPois` 排序取 Top，标「估算」。

### P2 可复用组件（前端，先抽组件后落页面）
- **新建** `ScreenRadar`（SVG 5 轴雷达，0~100，单多边形 + 轴标签）。
- 复用/抽取现有屏组件：折线图、堆叠柱、热力矩阵、漏斗、KPI 卡、承载/进度条、`AmapContainer`、`ScreenCard/Panel`、`PlaceholderTag`。
- 颜色/边框/阴影统一走 `app/src/app/screen/screen-theme.css` 的 CSS tokens（深色主题）。

### P3 融合页面组装（`/screen/command`）
- RSC 外壳渲染 5 列固定栅格（3840×1080，按视口等比缩放）；慢变面板 RSC 直读 repo。
- 顶栏（标题+时钟+天气）/ Footer（导出/刷新）。
- `/screen` index 顶部加入口卡。

### P4 实时联动（client live 岛）
- 轮询易变指标：occupancy / alerts / dispatch / weather / parking（沿用 `/api/screen/*` + 15s TTL）。
- SSE：`slot_changed` / `checkin_event` / `iot_event` / `parking_state`。
- **PRD 红线4**：承载达瞬时承载量 90% → 大屏**闪红**（复用 `CIRCUIT_BREAK_RATIO`）。

### P5 验证
- `pnpm lint`（含 eslint-boundaries）+ `pnpm exec tsc --noEmit` + 限速 `pnpm build`（先停 dev/docker，按编译纪律）。
- CDP 真机：接管 Chrome（已连 `10.7.0.2:9222`），3840 视口打开 `/screen/command` vs mockup **逐面板视觉核对** + 截图。

### P6 上线 & 收尾
- 推 `deploy-demo` 自动部署 + 线上实测三端点 + 整屏。
- 缺口①（POI 阈值/在园计数真值）与 AQI 接入登记 `docs/待办清单.md`。
- 本计划状态在评审通过、各项 `fix` 后更新。

## 5. 风险 / 取舍

- **中央地图**：见决策③风险。
- **示例数据下调度面板**：当前 seed 命中特殊态（停车满载+设备告警）；若清理后多为 `calm` 空态，演示特殊态需造触发数据。
- **PII 铁律**：大屏所有端点只出聚合/计数/状态枚举，绝不返回 Booking/黑名单/申诉原始行（沿用 `/api/screen/[metric]` 既有白名单约束）。
- **资源纪律**：build 极吃内存，须先停 dev + `docker compose down` 再限速 build（见 CLAUDE.md）。

## 6. 验收口径

- 每面板渲染真实数据或诚实占位/估算标注，无编造数据、无孤立英文。
- 我（实现方）自检通过仅标 `fix`；`pass` 由独立评审真机验收后标。

# 长秋山智慧景区 · 项目架构总览

> 仓库级架构文档。讲清**整个交付的全貌**：三端产品、两套子工程、技术栈、数据流与文档导航。
> 后端深度设计见 [`B端技术架构.md`](./B端技术架构.md)；需求见 [`PRD.md`](./PRD.md)；UI 全局规范见 [`../prompts/B-design-system.md`](../prompts/B-design-system.md)。

## 1. 项目定位

长秋山森林公园**官方营销与运营管理平台** + **数字孪生指挥中心**。一体化闭环：宣传 → 预约 → 活动 → 导览 → 数据 → 指挥调度。

> 🔴 **全局红线（贯穿三端）**：免费开放、分时预约制——全园不设门票、不收费、仅预约。「票务/票价/购票/退款」一律重构为「预约/名额/核销」；微信支付仅用于活动报名费等二消，**不进入入园流程**。
> 权威定义见 [`PRD.md`](./PRD.md)，技术落点见 [`B端技术架构.md` §6](./B端技术架构.md)。

## 2. 三端产品矩阵

| 端 | 用户 | 形态 | PRD 章节 | 一期状态 |
|---|---|---|---|---|
| **C 端** 运营小程序 | 普通游客 | 微信小程序 | 二 | 预约/AI问答/停车导览/活动报名 必做 |
| **B 端** 管理后台 | 景区运营人员 | Web 后台 | 一 | 本仓库后端 `app/` 落地中 |
| **大屏** 数字孪生 | 运营/指挥 | Web 大屏 | 三 | 一期完成 PRD + UI;部分纳入开发 |

> 一期范围：基础宣传、预约、AI 问答、活动、导览、停车、客流/画像六大分析、运营宣传一张图大屏。**资讯模块仅 PRD+UI**;**景区安防一张图本期不做**。

## 3. 仓库结构（双子工程 + 工作区）

仓库根是工作区（文档 + 提示词 + UI 归档），两套**互相独立、各自自包含**的子工程：

```
Changqiushan/
├── docs/                       # 文档:PRD / 项目架构(本文) / B端技术架构
├── prompts/                    # Stitch 提示词(A*=C端 · B*=后台 · C*=大屏 · fix-*=修订)
│                               #   + B-design-system.md(UI 全局规范,与后端同源)
├── UI/  UI_final_v3/  ...      # UI 设计稿截图归档 + 每页 DESIGN.md
├── logs/                       # Stitch 会话日志(session-*.jsonl)
│
├── scripts/   ◀── 子工程①:Stitch UI 工具链(npm 自包含)
│   ├── package.json            #   ws + cheerio
│   ├── node_modules/
│   ├── lib.js / session.js     #   CDP 核心库
│   └── *.js                    #   生成/截图/验证/画布整理脚本
│
└── app/       ◀── 子工程②:B 端后台应用(pnpm 自包含)
    ├── package.json            #   Next.js 16 + Prisma 7 + ...
    ├── prisma/                 #   多文件 schema + migrations
    └── src/{app,modules,infrastructure,shared,lib}/
```

**关键纪律**：`scripts/` 用 **npm**，`app/` 用 **pnpm**，根目录**不是** npm 项目，两套包管理器不混。详见 [`../CLAUDE.md`](../CLAUDE.md)。

## 4. 子工程① — Stitch UI 工具链（`scripts/`）

**职责**：从 PRD 自动化生成三端 39 页 UI 设计稿。

```
PRD → 拆页 → 写提示词(prompts/) → CDP 驱动 Stitch AI 设计 → 三点验证 → 截图 → 归档(UI/)
                                         ↑ 中文校验 / 红线词检查 / 视觉差异
```

- **机制**：Node 经 Chrome DevTools Protocol（`--remote-debugging-port=9222`）操作真实 Chrome 里的 Stitch，非 headless。
- **核心库**：`lib.js`（CDP 连接/发 prompt）、`session.js`（节点快照 + JSONL 日志）。
- **已知坑（已沉淀为记忆）**：① batch 模板化 prompt 只前几个生效→串行+独特锚点;② 改 prompt 概率分叉新页→节点数 diff 检测 fork;③ 完成判定看高度稳定+fork 双信号。
- 详见 [`../scripts/README.md`](../scripts/README.md)。

> 此工具链是**交付期产物**，UI 稿定稿后即冻结;与运行时后端无耦合。

## 5. 子工程② — B 端后台应用（`app/`）

**技术栈**：Postgres 18 + Next.js 16(App Router) + React 19 + Prisma 7 + TypeScript(strict)。

**架构范式**：模块化单体（Modular Monolith），`eslint-plugin-boundaries` 在 lint 期硬约束分层。

**8 业务模块**对齐 PRD B 端 5 大分组：`content` · `booking`+`checkin`+`riskcontrol` · `traffic` · `analytics` · `iot` · `system`。

**实时链路**（已打通）：Postgres trigger → `pg_notify` → pg-listen → 进程内 bus → SSE → 浏览器。

> 分层规则、模块明细表、标准骨架、数据层规约、红线技术落点、路由结构、落地路线图 —— 全部见 [`B端技术架构.md`](./B端技术架构.md)，本节仅作索引。

## 6. 端到端数据流（运行时）

```
                         ┌─────────────────────────────────────┐
   游客(C端小程序) ──预约/核销──▶│                                     │
   闸机/IoT/停车 ──事件/心跳──▶│   B 端后台 app/  (Next.js + PG18)    │
   高德/AI/微信支付 ◀─第三方──▶│   - 双要素校验 · 库存事务 · 90%熔断   │
                         │   - PG trigger → NOTIFY → SSE        │
                         └──────────────┬──────────────────────┘
                                        │ 同一数据底座(秒级一致)
                       ┌────────────────┴────────────────┐
                  运营人员(B端后台)                  指挥(数字孪生大屏)
```

四条主链路（一句话概括，技术落点见 [`B端技术架构.md` §5/§6/§7](./B端技术架构.md)）：
- **写**：C 端/渠道/补录 → 双要素校验 → 库存事务扣减 → 落库。
- **核销**：闸机查预约库 → 时段有效性判定 → 核销 → `checkin_event` 广播 → 大屏在园人数。
- **熔断**：在园人数达承载力 90% → slot 暂停 + `slot_changed` 广播 → 停约入口 + 大屏闪红。
- **分析**：明细 → 定时刷快照表 → 多维聚合/下钻 → 报表 + Excel 导出。

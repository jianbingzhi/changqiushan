# 长秋山森林公园智慧景区·详细功能需求规格说明书（修正版）

> 红线约束：长秋山森林公园属于 **免费开放、分时预约制景区**——全园 **不设门票、不收门票费用、仅做预约**。本文档涉及"购票/票价/票务"等概念一律物理重构为"预约/名额/核销"；微信支付链路仅保留在"摄影大赛报名费"等极少数二消/活动场景中，不进入入园流程。

---

## 0. 项目总览

### 0.1 项目定位
长秋山森林公园官方营销与运营管理平台，是景区景点与游客之间的统一数字化入口；同步构建景区端的数字孪生指挥中心与大数据分析底座。

### 0.2 项目背景
* 长秋山森林公园已具备景区品牌助推力，但传统业务方式偏粗放，缺乏全数据驱动的运营机制。
* 景区需借助数字化手段实现"宣传—预约—活动—导览—数据—指挥调度"的一体化闭环。
* 配合教育研学群体与本地村民，构建可持续的智慧景区解决方案。

### 0.3 业务流程
* **游客端流程**：进入小程序 → 浏览景区介绍/活动信息 → 参与 AI 问答/生态科普 → 查看停车与导览信息 → **分时免费预约 → 现场扫码核销入园** → 形成行为数据。
  * *一期必要实现*：分时预约、AI 问答、停车导览、活动报名。
* **运营端流程**：发布活动/资讯 → 收集用户行为数据 → 通过大数据平台分析客流量、游客画像、出行偏好 → 优化运营策略与资源调度 → 在数字孪生大屏上联动指挥。
  * *一期完成产品需求设计 + UI 设计稿*，待确认后再做开发。

### 0.4 使用角色
* **普通游客**（C 端，使用微信小程序）。
* **景区管理运营人员**（B 端，使用 Web 后台管理系统及大屏端）。

### 0.5 覆盖区域
* **核心区域**：长秋山森林公园全域。
* **扩展区域**：景区周边道路、停车场及关联交通节点（为路况/停车服务覆盖）。
* **用户覆盖**：全国范围内通过微信小程序触达的游客，以及景区运营人员与第三方协作团队。

## 一、平台管理后台（景区业务管控中枢）

### 1.1 基础宣传管理
* **景区介绍维护**：管理综合景色、特色景点、生态保护成果等图文/视频素材，支持多端发布。
* **活动运营管理**：支持摄影大赛、登山比赛、自行车比赛等活动的信息发布、报名审核、获奖公示与素材归档；活动可挂载报名费（走微信支付，**与入园预约完全隔离**）。
* **AI 问答知识库**：维护景区专属问答语料（景点、动植物、生态科普、应急须知），训练大模型微调样本，支持闭环回流与人工纠偏。

### 1.2 预约管理中心（原"票务中心"全量重构）
* **功能描述**：管理全园免费预约名额的配额、时段分配、现场补录及爽约风控。
* **具体功能点**：
  * **分时预约配额配置**：支持按日期（常规日、节假日、特殊活动日）自主创建预约规则；可配置每日最大预约总库存（如 10000 人）、分时段上下线控制（`08:00-10:00` 2000 人、`10:00-12:00` 3000 人……）、单身份证/手机号单日最大预约人数限制（防黄牛刷号占位）。
  * **预约要素强校验（红线）**：所有预约单 **必须同时携带身份证号与车牌号** 两项关键要素，后台对身份证做格式与有效性校验、对车牌做规则校验（含新能源车牌）；无车出行的游客须在前端勾选"无车辆"声明位，后台落库记录但不参与停车联动。任何缺项或非法值由后台直接拒收。
  * **渠道预约接入**：统一管理自营小程序与外部渠道（高德地图、携程、美团等免费预约 API 接口）的库存切分与共享逻辑；外部渠道下单时 **必须同步传入身份证号与车牌号**，否则后台拒绝入库。
  * **现场特殊人群补录面板**：专为现场未预约游客（不便使用智能手机的老人、外籍游客）准备；窗口工作人员录入身份证/护照号 **及车牌号**，一键补录预约记录并激活入园权限。
  * **用户爽约风控安全锁**：
    * *触发规则*：可配置"用户在指定天数内累计爽约（预约成功但未到园核销且未在截止时间前取消）达 X 次"。
    * *熔断惩罚*：自动拉黑该姓名/身份证/手机号，未来 Y 天内禁止在线预约。
    * *申诉通道*：游客可提交申诉材料，由后台人工复核解锁。

### 1.3 出行服务（高德地图能力对接）
* **API：道路实时路况查询**：查询具体道路的实时拥堵评价、拥堵路段、拥堵距离、拥堵趋势。
* **API：矩形区域实时路况查询**：查询指定矩形地理范围的实时拥堵情况和各拥堵路段信息。
* **API：多边形区域实时路况查询**：查询指定多边形地理范围的实时拥堵情况和各拥堵路段信息。
* **API：周边实时路况查询**：查询某中心点周边半径范围内的实时拥堵情况和各拥堵路段信息。
* **地图 APP：停车场动静态上图**：停车场满闲动态数据接入，停车位余量提前获知，避免拥堵。
* **地图 APP：拥堵分流**：综合分析地图停车、交通等大数据，在用户导航的行前、行中实现停车场级分流引导。

### 1.4 数据可视化与分析（运营端，B 端报表）
* **客流分析**：多维度对比、占比分析，支持导出 Excel。
* **热力图分析**：到访热力分布、客源热力分布。
* **来源分析**：来源分布行政图，可下钻至省/市/区县。
* **用户画像**：游客基本特征、出行偏好、APP 使用偏好等多维度详细分析（指标矩阵详见第三章数字大屏）。
* *资讯模块*：一期完成产品需求设计 + UI 设计稿，待确认后再行开发。

### 1.5 物联网设备监控（IT 运维）
* **实时设备列表**：全量收录智能闸机、高清监控摄像头、智能广播喇叭、智慧路灯等资产。
* **状态与心跳监测**：实时计算设备在线率、网络延时（ms）与丢包率。
* **闸机核销联动**：智能闸机不再校验"门票订单"，而是通过 API 高频请求后台的"预约数据库"，判定当前身份证/核销码是否在 **当前时段** 有效；同时停车场入口闸机基于预约时绑定的 **车牌号** 自动识别放行并预扣车位资源，秒级反馈通行结果。

## 二、长秋山森林公园运营小程序（游客移动端）

### 2.1 登录
* **授权手机号码**：基于微信小程序原生能力，一键授权获取手机号；首次进入时仅获取微信 OpenID 完成轻量识别，**预约下单环节再触发实名认证**，降低拉新阻力。

### 2.2 首页
* **平台 Logo**：固定品牌位。
* **轮播图**：后台可配置 Banner，支持内外部跳转。
* **景区宣传**：展示新景区介绍、特色景点、自然风光、生态保护成果。
* **快捷入口**：预约参观、AI 问答、停车查询、导览地图、活动报名。

### 2.3 免费分时预约（原"购票流"去资金熔断）
* **无感预约组件**：游客点击"立即预约"，进入日历选期与时段下拉菜单（实时显示剩余库存，如"14:00-16:00 剩余 120 名额"）。
* **预约必填项（强约束）**：
  * **身份证号**：每位入园人员均须录入真实身份证号（支持军官证/护照作为替代证件），用于实名核销、爽约风控与公安系统联动。可快捷调取微信实名信息一键带入，亦可手动输入；后台对身份证号做格式校验与有效性校验。
  * **车牌号**：必须录入入园车辆车牌号（含新能源车牌），用于停车场入场闸机自动识别、车位联动与拥堵分流。无车出行游客须主动勾选"无车辆"声明，否则不允许提交预约。
  * **入园人员人数**：受 **后台配置的每日可预约总量及单证件单日上限** 约束。
* **提交规则**：**彻底去除微信支付跳转链路**，身份证 + 车牌号 + 时段均合法后，点击提交直接触发预约成功，无任何资金流。
* **订单管理**：查看预约状态、预约记录、协议条款（含游园须知与隐私协议）。
* **自助取消机制**：为规避爽约处罚，提供一键"取消预约"按键，并配置截止时间规则（如必须在预约时段开始前 30 分钟取消），释放的库存瞬间自动回滚到大盘。
* **动态电子核销码**：生成用于过闸的电子二维码；二维码采用 **动态加密机制（防截图，30 秒自动刷新）**。
* **入园状态 Badge**：清晰展示当前预约单状态（待履约、已核销、已取消、已爽约）。

### 2.4 AI 智能问答
* **知识图谱**：接入大模型 API，结合景区专属知识库（景点、活动、动植物、生态科普）。
* **多轮对话**：支持上下文理解，提供连贯响应。
* **聊天记录**：自动保存历史对话，便于回顾与客服转人工。

### 2.5 活动模块
* **活动报名**：摄影大赛、登山比赛、自行车比赛等活动一键报名（仅活动报名费等二消场景走微信支付，与入园解耦）。
* **活动筛选**：按类型、时间、报名状态筛选。
* **活动评价**：用户提交活动评价并附图，运营审核后展出。

### 2.6 导览
* **停车导航**：
  * 停车场位置上图、剩余车位动态展示。
  * 路线推荐与拥堵实时提醒（联动高德拥堵分流 API）。
* **餐饮/服务推荐**：烧烤场地、卫生间、餐饮、便利店等 POI 标注。

### 2.7 我的中心
* **待选项目**：通过微信 OpenID 识别用户（无需强制实名认证；仅预约下单流程触发实名）。
* **我的订单**：查看预约单、预约记录及核销状态。
* **我的活动**：已报名记录、活动凭证。
* **我的咨询**：查看历史 AI 对话记录。
* **常见问题快捷入口**：如预约时间、交通方式、**开放时间**（注：原文档"门票价格"项已删除，景区不设门票）。
* **设置**：意见反馈、关于我们、客服入口、退出登录。

## 三、大数据平台与数字孪生大屏

由于去除了门票资金流水，大屏端的指标矩阵围绕"客流—预约—画像—运营"四象限重构。

### 3.1 旅游产业与综合运营分析面板（原"营收大盘"重构）
* **资金线物理剥离**：彻底移除"今日门票总营收、各票种销量占比、退款金额"等指标。
* **预约转化漏斗看板**：实时计算并展示"今日总预约量 → 实时入园核销量 → 预约到园率（履约率）"。
* **爽约态势雷达**：滚动统计今日截止当前时段的爽约总人数、爽约率走势图，以及被系统风控拦截的黑名单人数统计。

### 3.2 综合态势感知面板（大屏核心中央）
* **瞬时承载力预警**：实时在园总人数、今日累计入园总人数；当在园人数接近瞬时最大承载量（达 90%）时，大屏整框闪烁红色预警，**同时管理后台自动熔断小程序端的"当日预约入口"**。
* **分时预约到园曲线**：对比展示"预约量预测曲线"与"实际到园核销曲线"，辅助预判客流高峰，提前调配保安和观光车运力。

### 3.3 实时路况地图（大屏地图层）
* **API：周边实时路况查询**：查询某中心点周边半径范围内的实时拥堵情况和各拥堵路段信息汇总。
* **API：矩形区域实时路况查询**：查询指定矩形地理范围的实时拥堵情况和各拥堵路段信息。
* **API：道路实时路况查询**：查询具体道路的实时拥堵评价、拥堵路段、拥堵距离、拥堵趋势。
* **API：多边形区域实时路况查询**：查询指定多边形地理范围的实时拥堵情况和各拥堵路段信息（含跨地图拼接）。

### 3.12 预约趋势分析（共 14 项细分指标）

### 3.13 预约分时热力图（共 8 项）
> 以"预约时段"为格子，跨日/周/月铺成热力矩阵，直观识别冷热档期与瓶颈时段。
1. **日维度热力图**：以当日 30 分钟（或 1 小时）粒度横轴 × 时段名额纵轴，按预约率涂色。
2. **周维度热力图**：以一周 7 天 × 24 小时格子涂色，叠加节假日标记。
3. **月维度热力图**：以一月 N 天 × 时段格子涂色，自动识别国家法定节假日/特殊活动日。
4. **20POI 阈值预警设置**：可针对景区内 TOP20 热门 POI（核心景点、观景台等）单独设置预约阈值；预约量超过阈值时格子描红边并触发后台短信/站内信告警。
5. **阈值动态调整**：阈值支持按节假日、特殊活动日、瞬时承载力红线动态切换配置档案。
6. **联动熔断**：任一时段达 90% 阈值时，自动联动 3.2 综合态势感知与 1.2 预约管理中心，暂停当日该时段在线预约入口。
7. **历史回放**：可回看任意历史日/周/月的预约热力图，用于复盘节假日波峰波谷。
8. **数据下载**：热力图原始数据可导出 Excel。

### 3.14 数字孪生·景区（底座平台）

> 参考原型：`3.png`（"长秋山森林公园 导览图 Tour Map Of Changqiu Mountain Forest Park"）。该原型仅作补充示意，最终功能以本节文字描述为准；只增不减。

#### 3.11.1 底座能力
* **3D 实景建模**：基于无人机倾斜摄影/激光点云，构建长秋山全域高精度实景三维模型，作为所有一张图的统一底图。
* **数据融合层**：汇聚预约、闸机核销、停车、客流、画像、设备状态等多源数据，统一时空索引，按主题向上层一张图开放查询接口。
* **IoT 设备接入**：通过 MQTT/HTTP/私有协议接入智能闸机、监控摄像头、广播喇叭、智慧路灯、停车场地磁等终端，设备孪生体在 3D 场景中可视化呈现。
* **统一渲染引擎**：提供大、中、小场景一体化渲染能力，支持 Web/大屏/移动端多终端访问，向上层"运营宣传一张图"等专题提供基础渲染与交互能力。
* **空间分析能力**：通视分析、缓冲区分析、路径分析等基础 GIS 算子，供运营/调度场景按需调用。

#### 3.11.2 导览图底图与视角切换（依据 3.png 提炼）
* **手绘风格导览底图**：以景区官方导览图（手绘插画风格）作为 2D 默认底图，覆盖全园山体、林区、河流、建筑群、主要道路等要素，标题区固定显示"长秋山森林公园 导览图 / Tour Map Of Changqiu Mountain Forest Park"。
* **2D ↔ 3D 视角一键切换**：右上角提供"3D 视图"切换按钮，支持在手绘导览图与高精度三维实景模型之间无缝切换，相机姿态与中心点保持一致，切换无跳变。
* **基础地图交互**：平移、缩放、复位、罗盘、视角倾斜/旋转、最小地图缩略图等控件常驻。

#### 3.11.3 顶部实时指标卡（KPI 概览）
* 默认置于地图左上角，至少包含三个核心指标卡，数值实时刷新：
  * **入园人数**：当前在园人数实时值（示例：1,485）。
  * **开放区域/设施比**：当前已开放区域或设施数 / 总数（示例：6/8）。
  * **告警/事件总数**：当日累计告警或重点事件数量（示例：12）。
* 指标项支持后台可配置，运营人员可自行替换为"今日累计预约""今日核销量""停车场剩余车位"等其他统计口径。

#### 3.11.4 数字孪生面板（右侧抽屉式）
面板标题"数字孪生面板"，可折叠/展开，自上而下包含以下子模块：
* **告警预警**：实时滚动展示告警事件，区分等级（紧急/重要/提示），点击告警条目联动地图定位至事发点位。
* **设备数据**：以小型仪表/趋势图展示重点设备（闸机吞吐、停车场负荷、广播在线率、路灯能耗等）的实时读数与近 24 小时趋势。
* **设备运维**：分类统计在线/离线/故障设备数量（示例：6 在线、0 离线），点击数字下钻至设备清单。
* **区域分布**：以条形或环形图展示当前在园人数在核心景点/片区的分布占比，辅助调度。

#### 3.11.5 POI 图标与分类筛选
* **多类型 POI 标注**：在地图上以差异化图标标注景点、餐饮、停车、卫生间、补给站、观景台、应急避难点等 POI；图标支持悬浮高亮与点击弹出详情卡（图文 + 当前状态 + 跳转链接）。
* **底部图例 + 一键筛选**：右下角图例区列出 POI 分类色卡，点击色卡即可在底图上隐藏/显示对应类别图层，支持多选叠加。
* **底部信息条**：左下角预留地图显示信息区（坐标、比例尺、所属图层、当前模式等），方便大屏值守人员快速研判。

#### 3.11.6 联动与交互
* **指标卡 ↔ 地图联动**：点击顶部指标卡可在地图上高亮对应区域（如点击"入园人数"高亮入园闸机所在山门）。
* **面板 ↔ 地图联动**：右侧任一面板条目点击即可定位到对应地理坐标，并在 3D 模式下自动俯冲到合适视角。
* **大屏 ↔ 后台联动**：大屏所有数据均与后台预约/IoT/客流模块共用同一数据底座，秒级一致。

#### 3.11.7 本期红线
* 本数字孪生底座 **不承载安防一张图功能**；安防类视频流、行为分析、电子围栏告警等内容均不在本期建设范围内。
* 3.png 仅作视觉参考，**配色、版式、图标样式以一期 UI 设计稿为准**；本节文字描述的功能清单为最终交付边界。

### 3.15 运营宣传一张图（数字孪生·五专题）
1. **景区地图基础展示**：依托 GIS，提供 2D/2.5D/3D 多维度展示，支持平移、缩放、场景切换复位、智能搜索、多视角浏览、地表直线距离与导航距离查询、二维/三维面积查询、地图标签、属性信息查询、位置等功能；界面友好简洁。
2. **景区运营专题**：深度融合景区大数据，以热力图、数据标签等形式实时可视化展示客流分布、车流密度及关键经营 KPI；支持点击场景要素联动查询详细数据。
3. **设施状态与资源调度专题图**：实时接入并可视化停车场设施运行状态；通过三维场景展示设施负荷、人员位置及资源分布，辅助管理者异常预警与资源优化调度。同时联动展示各入园智能闸机在当前时段的核销吞吐量速率，若某山门因游客扎堆导致核销排队过长，大屏立刻亮黄灯提示调配人手。
4. **多维度数据智能分析专题图**：集成客流、消费、客源等多维度数据；通过统计图表与三维地图双向联动深度可视化分析，支持按空间区域、时间范围、客群属性等多重条件联动筛选与下钻。
5. **沉浸式三维景区漫游专题图**：利用高精度实景三维模型，预设多条主题漫游路径；可在飞行漫游中联动展示景点多媒体介绍，服务宣传推广与虚拟游览展示。

## 四、关键非功能与红线复述

* **入园即预约、预约即入园**：全流程不出现"门票/票价/退款"字样；所有"票务"语义统一替换为"预约/名额/核销"。
* **预约双要素强约束**：身份证号 + 车牌号 是所有预约单（线上小程序、外部渠道、现场补录）的必填项，后台双重校验，任一缺失或非法即拒收。
* **支付链路隔离**：微信支付仅出现在活动报名费等二消模块，**入园主流程不调起任何支付组件**。
* **预约公平性**：单身份证/手机号单日预约上限 + 爽约风控双约束，杜绝黄牛占位。
* **承载力红线熔断**：在园人数达瞬时最大承载量 90% 时大屏闪红、小程序自动停售当日剩余名额。
* **数据可下载**：所有客流/画像/偏好类报表必须支持 Excel 导出。
* **一期范围**：基础宣传、预约、AI 问答、活动、导览、停车、客流/画像六大分析、运营宣传一张图大屏均纳入一期；资讯模块仅完成 PRD + UI，待确认后再开发；**景区安防一张图本期不做**。
* **显示载体与最小可视区**：数字孪生大屏按 **1920×1080 固定分辨率**设计与验收（B104 超宽融合指挥总屏为 3840×1080）；平台管理后台以**笔记本可视区**为最小支持目标（约 1280×720 及以上，含常见 1440×900 笔记本减去浏览器边框后的 ~1324×804）；**明确不支持手机端访问后台与大屏**（游客侧移动能力由小程序承载）。〔2026 年 7 月 29 日 由甲方口述确认，作为 round-01 验收判据〕
* **界面可读性**：B 端后台与数字孪生大屏的文本对比度须满足 **WCAG AA（正文 4.5:1）**；配色须由设计 token 统一管理并支持深/浅双主题，不得在页面内写死色值。具体色值与 token 清单以设计正本为准，本文档不复述。〔2026 年 7 月 29 日 确认〕
